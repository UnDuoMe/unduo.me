# @-/me.unduo.components.setup.portal

Duo device portal guidance and example enrollment screenshots. `portalStep(school, choices, page)` builds the step with a **Your school** menu of `choices` and the chosen institution's portal link, note and source, from the page's `#setup-schools` template, then "Press **Continue** when you see a page like this:" over two examples of Duo once you're signed in, in a narrow window and a wide one, with only the device's name and number blurred. `authenticateStep(school, page)` builds the next step: authenticate with Duo as usual, with a passcode or a push, and press **Continue** on the My Settings & Devices page, shown with only the devices' names and numbers blurred. `portalInstructions(school, page)` builds the instructions the QR step shows: Tablet → Android → I have Duo Mobile installed. When `school.duoPrompt` is `universal` (its `data-duo-prompt` in `#setup-schools`), both steps name the Universal Prompt's labels instead: the page with **Add a device**, then Add a device → Duo Mobile → I have a tablet → Next. `portalScreenshots(image, sets)` writes the sets the file's institutions use, and `screenshotSet(university)` picks each institution's: `traditional`, UofT's, with its logo and two signed-in examples; `generic`, the same with the logo painted out, for Other; `universal`, Waterloo's (from its IT knowledge base, with its logo), with one signed-in example because Duo's prompt looks the same in any window; and `western`, the generic set with Western's own My Settings & Devices, captioned with the way there from Western Identity Manager. A settings screenshot with a caption is a `<figure>`; one without is a bare `<img>`. `portalScreenshots`, from `@-/me.unduo.components.setup.portal/server`, writes each set's captions and pinned URLs into three `<template>`s named for it: `#portal-signed-in-<set>`, which `portalStep` copies, `#portal-settings-<set>`, which `authenticateStep` copies, and `#portal-screenshot-figures-<set>`, which `portalInstructions` copies; the build checks their URLs and pins, so they stay in the page's HTML. The link calls the setup page's `popup` to open the portal in a small window beside the steps, and `#portal-url` shows the same link with a Copy button for pasting into a new window.
